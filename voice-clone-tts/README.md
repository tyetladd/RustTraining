# voice-clone-tts

Озвучка произвольного текста голосом из MP3-файла.

На вход подаются два параметра: **запись голоса** (mp3/wav/m4a/…) и **текст**.
Скрипт распознаёт запись (Whisper), определяет по ней язык, строит из неё
профиль диктора, расставляет в тексте ударения и `ё` через
[silero-stress](https://github.com/snakers4/silero-stress) и синтезирует речь
клонированным голосом. Русский и английский работают из коробки, другие языки
добавляются конфигом.

```
mp3 ──► декодирование ──► ASR (язык + транскрипт) ──► выбор чистых сегментов ──► профиль диктора
                                                                                     │
текст ──► нормализация ──► ударения (silero-stress) ──► нарезка на чанки ────────────┤
                                                                                     ▼
                                                                          backend.synthesize
                                                                                     │
                                                                  склейка · громкость · файл
```

## Быстрый старт

```bash
pip install -e '.[all]'                 # или см. «Установка» ниже
export VCTTS_ACCEPT_COQUI_LICENSE=1     # подтверждение лицензии весов XTTS

# сначала проверить запись — до того, как тратить время на обучение
vctts check sample.mp3

# самый короткий путь: голос + текст -> wav
vctts speak -v sample.mp3 -t "Привет! Это мой клонированный голос." -o out.wav

# язык не указываем — он определяется по записи
vctts speak -v sample.mp3 -f article.txt -o article.mp3

# один раз построить профиль и потом переиспользовать (быстрее)
vctts profile build sample.mp3 -o profiles/anna
vctts speak -p profiles/anna -t "Второй текст тем же голосом." -o second.wav

# посмотреть, что реально уедет в модель, без синтеза
vctts speak -p profiles/anna -f article.txt --dry-run

# Silero TTS + клонированный голос (нужна обученная VC-модель, см. ниже)
vctts voice train -p profiles/anna -o voices/anna --vc rvc
vctts speak -b silero --voice-model voices/anna --transpose auto \
      -t "Тот же текст моим голосом." -o cloned.wav

# только расстановка ударений
vctts stress "Старинный замок на горе, а на двери замок"
# -> Стар+инный з+амок н+а гор+е, +а н+а двер+и зам+ок
```

## Установка

```bash
pip install -e .                # ядро: numpy, soundfile, soxr (без нейросетей)
pip install -e '.[stress]'      # + silero-stress (torch) — ударения и ё
pip install -e '.[asr]'         # + faster-whisper — распознавание и детект языка
pip install -e '.[xtts]'        # + coqui-tts — клонирование голоса (XTTS-v2)
pip install -e '.[silero]'      # + Silero TTS (готовые голоса, без клонирования)
pip install -e '.[all]'         # всё сразу
```

`ffmpeg` нужен только если ваша сборка `libsndfile` не умеет читать входной
формат: MP3 в libsndfile ≥ 1.1 читается и пишется без него.

Проверить, что доступно в текущем окружении:

```bash
vctts backends     # ✓/✗ по каждому движку + команда установки
vctts languages
```

## Бэкенды

| backend  | клонирует голос | языки | ударения `+` | частота | лицензия весов |
|----------|-----------------|-------|--------------|---------|----------------|
| `xtts` (по умолчанию) | да, zero-shot | ru, en + 15 других | нет (снимаются, `ё` остаётся) | 24 кГц | Coqui CPML, **некоммерческая** |
| `silero` | нет, только штатные дикторы | ru, en, uk | да, нативно | 48 кГц | MIT |
| `dummy`  | нет | любые | нет | 24 кГц | — |

* **xtts** — основной путь. Zero-shot клонирование: модель принимает несколько
  секунд эталонной речи и говорит этим голосом. Веса скачиваются при первом
  запуске (~1.8 ГБ) и распространяются по
  [Coqui Public Model License](https://coqui.ai/cpml) — только некоммерческое
  использование. Пока вы не подтвердите это через
  `VCTTS_ACCEPT_COQUI_LICENSE=1` или `--accept-coqui-license`, скачивание не
  начнётся.
* **silero** — голос не клонирует: доступны только штатные дикторы
  (`aidar`, `baya`, `kseniya`, `xenia`, `eugene` для русского). Зато он
  единственный, кто ест разметку silero-stress как есть (`гот+ов`), быстр на
  CPU и лицензирован под MIT. По умолчанию берётся `v5_5_ru`; другую модель
  можно выбрать через `--backend-option model_id=v5_ru`, голос — через
  `--backend-option voice=baya`. Параметры `put_accent`/`put_yo` из v3/v4 в v5
  отсутствуют, бэкенд это обрабатывает сам.

  Чтобы получить клонированный голос с этим движком, нужен отдельный шаг
  преобразования тембра (voice conversion) поверх синтеза — см. «Клонирование
  голоса с Silero TTS».
* **dummy** — без моделей вообще: гудок на частоте основного тона диктора.
  Нужен для тестов конвейера и CI.

Свой движок добавляется одним классом — см. «Расширение».

## Чего ждать по качеству

Результат складывается из трёх слоёв, и они удаются по-разному.

| слой | что определяет | чего ждать |
|------|----------------|------------|
| текстовый фронтенд + silero-stress | произношение, ударения, омографы, числа и даты | сильная сторона: ~4 млн словоформ и ~2.2 тыс. омографов, ошибок в ударениях почти нет |
| Silero TTS v5 | интонация, ритм, дикция | естественная русская речь дикторского уровня |
| voice conversion (RVC) | тембр | узнаваемо ваш голос, но не неотличимо |

Ключевое ограничение, которое стоит понять заранее: **VC переносит тембр, а не
манеру речи**. Темп, паузы, мелодика фразы останутся от диктора Silero. Со
стороны это звучит как «человек с вашим голосом, но с чужой манерой» — для
озвучки текстов это обычно нормально, для имитации конкретного человека в
диалоге — заметно.

Типичные артефакты RVC поверх TTS: металлический призвук на шипящих, «ватные»
согласные, редкие срывы высоты тона на длинных гласных. Они тем заметнее, чем
хуже исходная запись и чем больше разница по высоте между диктором Silero и
вашим голосом, поэтому берите диктора того же регистра
(`--backend-option voice=aidar` для мужского голоса) — тогда `--transpose auto`
даст небольшой сдвиг и артефактов будет меньше.

Для сравнения: XTTS-v2 (`-b xtts`) копирует и тембр, и отчасти манеру речи без
всякого обучения, но хуже читает по-русски (ударения ему не передать) и его
веса нельзя использовать коммерчески. Коммерческие сервисы вроде ElevenLabs по
естественности пока впереди обеих связок.

## Как записать эталон

Качество исходной записи влияет на результат сильнее, чем число эпох обучения:
VC копирует всё, что слышно, включая шум, эхо и артефакты кодека.

**Целевые параметры**

| параметр | нужно | почему |
|----------|-------|--------|
| длительность | 15–30 минут чистой речи (минимум 5) | меньше — тембр узнаётся хуже, больше 30 почти не улучшает |
| формат | WAV 44 100 или 48 000 Гц, 16/24 бита, моно | на 16 кГц теряются верхние форманты — тембр не восстановить |
| если только mp3 | от 192 кбит/с | артефакты кодека выучиваются вместе с голосом |
| уровень | пики около −6 dBFS, RMS ≈ −20 dBFS | клиппинг портит тембр сильнее, чем тихая запись |
| шум | SNR 30 дБ и выше | фоновый шум клонируется вместе с голосом |
| помещение | без эха: мягкая мебель, шторы, не ванная и не пустая комната | реверберация въедается в модель и не убирается потом |

**Что читать**

Готовый материал лежит в [`recording-script/`](recording-script/): двенадцать
блоков разного типа речи на 16–20 минут чтения плюс темы для свободной речи,
и отдельный набор фраз для проверки результата после обучения. Разнотипность
важнее объёма — модель выучивает только те интонации, которые услышала.

**Как писать**

* один микрофон, одна комната, одна сессия — не склейка из разных условий;
* микрофон на 15–25 см, чуть сбоку от рта, с поп-фильтром или хотя бы под углом;
* читайте разнородный текст: обычная проза, вопросы, числа, имена — модель
  выучит только те звуки, которые услышит;
* ровный темп и громкость, без шёпота и крика, без пения;
* отключите «улучшение голоса», шумоподавление и автоусиление (Zoom, Discord,
  диктофон телефона, гарнитуры) — их артефакты выучиваются;
* никакой музыки и посторонних голосов в фоне; длинные паузы не страшны, они
  вырезаются автоматически.

**Проверьте до обучения**

```bash
vctts check запись.wav              # для обучения VC
vctts check запись.wav --purpose xtts   # для zero-shot клонирования XTTS
```

Команда меряет длительность речи, формат, уровень, клиппинг, SNR и основной
тон, ставит вердикт и подсказывает подходящих дикторов Silero:

```
запись.wav: запись годится

  длительность   : 18.4 мин (речи 16.1 мин)
  формат         : WAV PCM_16 48000 Гц, каналов 1
  уровень        : RMS -20.3 dBFS, пик -6.1 dBFS
  клиппинг       : 0.000 % сэмплов
  шум            : SNR ~34 дБ, тишины 12 %
  основной тон   : 118 Гц (male)
  дикторы Silero : aidar, eugene

  ✓ речи 16.1 мин — достаточно
  ✓ частота дискретизации 48000 Гц
  ✓ клиппинга нет
  ✓ SNR ~34 дБ
```

Пять минут на проверку дешевле, чем несколько часов GPU на записи, которую
всё равно придётся переписать.

## Клонирование голоса с Silero TTS

Сам Silero TTS клонировать голос не умеет: у публичных моделей фиксированный
набор дикторов (`aidar`, `baya`, `kseniya`, `xenia`, `eugene`), входа для
эталонного аудио или эмбеддинга диктора нет. Поэтому клонирование сделано
второй ступенью — **voice conversion**: Silero произносит текст штатным
голосом, а обученная на вашем дикторе VC-модель переносит на него тембр.
Произношение, ударения и интонация остаются от Silero, меняется тембр.

```
текст → silero-stress → Silero TTS (xenia) → voice conversion → голос из записи
                                                    ↑
                                    модель, обученная на вашей записи
```

Это уже настоящее обучение, а не few-shot адаптация: нужны минуты речи и GPU.

### Как обучить и использовать

```bash
# 1. профиль (заодно покажет качество записи и распознает язык)
vctts profile build sample.mp3 -o profiles/anna

# 2. обучение голоса: режет запись на клипы и запускает тулчейн
vctts voice train -p profiles/anna -o voices/anna --vc rvc --epochs 300

# только подготовить датасет и посмотреть, сколько получилось речи
vctts voice train -s sample.mp3 -o voices/anna --dataset-only

# 3. синтез: Silero говорит, VC-модель подменяет тембр
vctts speak -b silero --voice-model voices/anna --transpose auto \
      -t "Привет! Это мой голос." -o out.wav

vctts voice show voices/anna     # что за модель, на чём обучена
vctts converters                 # какие тулчейны доступны здесь
```

`--transpose auto` сам считает сдвиг в полутонах: медианная F0 синтезированной
речи против медианной F0 вашего диктора. Мужской голос поверх женского диктора
Silero обычно требует −8…−12 полутонов, и авторасчёт попадает туда же; при
`--transpose 0` тембр «поплывёт».

### Чем обучать

| `--vc` | тулчейн | установка | заметки |
|--------|---------|-----------|---------|
| `rvc` (по умолчанию) | [Applio](https://github.com/IAHispano/Applio), MIT | `git clone` + `pip install -r requirements.txt`, затем `VCTTS_APPLIO_DIR=/path/to/Applio` | актуальное семейство RVC, поддерживается; ближе всего к оригиналу |
| `sovits` | [so-vits-svc-fork](https://github.com/voicepaw/so-vits-svc-fork), MIT | `pip install -U so-vits-svc-fork` | ставится одной командой, но апстрим больше не развивается |

Проект не тянет их за собой: драйвер запускает внешний CLI (`svc …` либо
`python core.py …` в вашем чекауте Applio) и складывает результат в
самодостаточную папку модели:

```
voices/anna/
    voice_model.json     метаданные: тулчейн, эпохи, длительность датасета, медианная F0
    anna.pth             веса
    anna.index           индекс (RVC)
    dataset/dataset_raw/anna/clip_0001.wav …
```

### Что нужно по данным и железу

* **5–30 минут** чистой речи одного диктора. Датасет собирается из исходной
  записи целиком (а не из 60 с профиля) и режется на клипы до 10 с;
  при меньшем объёме `vctts voice train` предупредит, но не откажется.
* **GPU обязателен** для обучения: 6–8 ГБ VRAM хватает, 300 эпох на 10 минутах
  речи — это порядка нескольких часов на RTX 3060 и заметно меньше на 4090.
  На CPU обучение практически нереально.
* Инференс VC на GPU добавляет к синтезу немного (доли реального времени), на
  CPU — ощутимо медленнее реального времени.

> Статус: слой обучения и конвертации (подготовка датасета, запуск тулчейнов,
> хранение модели, авторасчёт транспонирования) покрыт тестами на подставных
> процессах, но сами Applio и so-vits-svc-fork в этом окружении не
> запускались — нет GPU и весов. Команды собраны по их текущим CLI.

## Обучение в облаке: Colab и Kaggle

GPU для обучения можно не покупать — бесплатных тарифов Colab и Kaggle хватает.
В репозитории лежат готовые ноутбуки:

* [`notebooks/colab_train_voice.ipynb`](notebooks/colab_train_voice.ipynb)
* [`notebooks/kaggle_train_voice.ipynb`](notebooks/kaggle_train_voice.ipynb)

Оба ставят проект и выбранный тулчейн, строят профиль из записи, обучают
VC-модель, проверяют результат связкой Silero + голос и отдают модель архивом.
Разница принципиальная:

* **Kaggle умеет считать в фоне.** `Save Version → Save & Run All` выполняет
  ноутбук на серверах Kaggle — браузер и ноутбук можно закрыть, обрыв связи ни
  на что не влияет. Запуск из редактора (`Run All`) — наоборот: такая сессия
  живёт, пока открыта вкладка, и вместе с ней пропадает всё в `/kaggle/working`.
  Первая ячейка ноутбука определяет режим по `KAGGLE_KERNEL_RUN_TYPE` и
  предупреждает до начала обучения, а не после. Kaggle-ноутбук написан именно под этот режим: он сам
  определяет, начинает с нуля или продолжает с чекпоинта прошлой версии, сам
  останавливает обучение до лимита сессии и не падает при этом, чтобы output
  успел сохраниться.
* **В бесплатном Colab фонового выполнения нет.** Вкладку нужно держать
  открытой, при обрыве связи сессия умирает (на Drive остаются чекпоинты, и
  прогон продолжается ячейкой resume). Фоновый режим есть только в Colab Pro+.

| | Colab (free) | Kaggle (free) |
|---|---|---|
| GPU | T4 16 ГБ, не гарантирован | P100 16 ГБ или T4 x2 |
| сессия | до 12 ч, отключение после ~90 мин простоя | до 9 ч для GPU |
| квота | плавающая, не публикуется | 30 ч GPU в неделю, сброс в субботу 00:00 UTC |
| фоновое выполнение | нет (только в Pro+) | да: Save & Run All считает без вас |
| что переживает обрыв | Google Drive | входные датасеты и output сохранённой версии |
| особые условия | — | нужен **Internet → On** (аккаунт с подтверждённым телефоном) |

### Как это устроено в ноутбуках

Обучение почти наверняка не уложится в одну сессию, поэтому состояние выносится
наружу, а прогон продолжается с последнего чекпоинта:

```bash
# первый запуск
vctts voice train -p profiles/anna -o "$WORK/voices/anna" --vc rvc --epochs 300 \
      --vc-option logs_dir="$WORK/logs" --vc-option save_every_epoch=25

# в новой сессии: датасет и признаки не пересчитываются
vctts voice train -p profiles/anna -o "$WORK/voices/anna" --vc rvc --epochs 300 --resume \
      --vc-option logs_dir="$WORK/logs"
```

`--vc-option logs_dir=…` уводит логи Applio из эфемерного чекаута в постоянную
папку (симлинком), иначе чекпоинты умрут вместе с сессией. У `sovits` всё и так
лежит внутри `-o`, поэтому опция ему не нужна. `--resume` переиспользует уже
нарезанные клипы и пропускает извлечение признаков.

Бюджет времени задаётся через `--vc-option timeout=<секунды>`: по его истечении
процесс обучения останавливается вместе со всеми порождёнными процессами, а
чекпоинты остаются — следующий прогон продолжит с них. Это то, что позволяет
уложиться в жёсткий лимит сессии, а не потерять всё на 9-м часу.

Ориентир по времени: 300 эпох на ~10 минутах речи — это несколько часов на T4,
то есть одна-две сессии Colab или одна сессия Kaggle с запасом. `save_every_epoch`
определяет, сколько работы стоит обрыв; `batch_size` уменьшайте до 4 при нехватке
памяти.

### Проверить конвейер без GPU

Нарезка и извлечение признаков считаются на CPU — обучение нет. Поэтому на
машине без CUDA (например, на MacBook) можно прогнать всё до обучения и
убедиться, что данные готовятся правильно:

```bash
vctts voice train -p profiles/anna -o voices/anna --stop-after extract
```

Конвейер остановится перед обучением и напечатает, сколько чего получилось:
фрагментов, признаков, строк в `filelist.txt`. Если что-то из этого пусто,
ошибка назовёт конкретную папку — Applio собирает `filelist.txt` как пересечение
имён в `sliced_audios`, `extracted`, `f0` и `f0_voiced`, и пустая любая из них
обнуляет обучение без внятного сообщения.

Стадии: `--stop-after dataset` (только нарезать записи), `preprocess`,
`extract`.

### Что может пойти не так

* **Конфликты pip.** Applio жёстко пинит `torch`, `transformers`, `gradio`
  поверх предустановленных в образе. Предупреждения ожидаемы; если после
  установки ломается импорт torch — перезапустите среду и выполните ячейки
  заново, пропустив установку.
* **Kaggle без интернета.** Без `Internet → On` не установятся пакеты и не
  скачаются предобученные веса; переключатель доступен только на аккаунте с
  подтверждённым телефоном.
* **Хранение на Drive.** Датасет — это сотни мелких wav; класть его на Drive
  нормально, но если I/O тормозит, укажите `--dataset-dir /content/dataset`
  (локальный диск) — при возобновлении он соберётся заново за секунды.
* **Модель дома.** Скачанная папка модели самодостаточна, но для синтеза на своей
  машине нужен тот же тулчейн (Applio или so-vits-svc-fork). Если локального GPU
  нет, проще синтезировать прямо в ноутбуке и забирать wav.

## Ударения и `ё` (silero-stress)

Для русского текста ударения решают больше, чем кажется: без них модель читает
омографы наугад. `silero-stress` покрывает ~4 млн словоформ и ~2.2 тыс.
омографов и заодно восстанавливает `ё`. Разметка ставится **перед** ударной
гласной:

```
Старинный замок на горе, а на двери замок
  ->  Стар+инный з+амок н+а гор+е, +а н+а двер+и зам+ок
```

Движки относятся к этой разметке по-разному, поэтому конвейер хранит текст во
внутреннем `+`-формате, а каждый бэкенд получает тот вид, который понимает
(`native_stress_style`):

| `--stress-style` | что уходит в модель | кому |
|------------------|---------------------|------|
| `plus`  | `гот+ов` | Silero TTS и большинство русских G2P |
| `acute` | `гото́в` (U+0301) | фронтенды, понимающие комбинирующий акут |
| `none`  | `готов`, но `ё` сохраняется | XTTS — символ `+` он не видел при обучении |

Порядок шагов важен: silero-stress не раскрывает цифры, поэтому нормализация
чисел идёт **до** расстановки ударений. Нормализатор разворачивает числа,
даты, проценты, валюты, время и сокращения:

```
В 2024 г. замок стоил 1 234 567 руб. Встреча в 10:30.
  ->  В две тысячи двадцать четвёртом году замок стоил один миллион двести
      тридцать четыре тысячи пятьсот шестьдесят семь рублей. Встреча в десять тридцать.
```

Отключается через `--no-stress` / `--no-normalize`, отдельные слова — через
`--ignore-word СЛОВО`.

## Профиль диктора («обучение»)

`vctts profile build` — это шаг адаптации под голос. Важно понимать, что это
**few-shot адаптация, а не дообучение градиентом**: из записи извлекаются
эталонные фрагменты и условные представления диктора, веса модели не меняются.
Для XTTS этого достаточно, чтобы узнаваемо скопировать тембр с 30–60 секунд
речи.

Что происходит внутри:

1. запись декодируется в моно 24 кГц;
2. считается отчёт о качестве (длительность, клиппинг, оценка SNR, доля
   тишины) — предупреждения печатаются сразу, плохой референс виден до синтеза;
3. Whisper расшифровывает запись, даёт язык и тайминги (без него — энергетический
   VAD, `--no-asr`);
4. сегменты ранжируются по уверенности ASR, склеиваются до 3–15 с и отбираются
   до `--ref-seconds` секунд чистой речи;
5. клипы обрезаются по тишине, выравниваются по громкости и пишутся в профиль.

```
profiles/anna/
    profile.json        метаданные, отчёт о качестве, выбранные сегменты
    transcript.json     полный вывод ASR
    refs/ref_01.wav     очищенные эталонные клипы, 24 кГц моно
    cache/xtts_latents.pt   кеш GPT-латентов и эмбеддинга диктора
```

Кеш латентов считается один раз и переиспользуется при каждом следующем
синтезе; если набор клипов изменился, он пересчитывается автоматически.

## Требования к железу

Замеры ниже сделаны на 4 vCPU без GPU (silero-stress) либо взяты как
ориентировочные для остального — цифры зависят от модели и длины текста.

| шаг | CPU (4 ядра) | GPU |
|-----|--------------|-----|
| silero-stress | загрузка 2.8 с, ~90 мс на фразу (измерено) | не нужен |
| faster-whisper `small` | ~0.3–0.5× RTF, int8 | ~0.05× RTF |
| XTTS-v2 синтез | ~1–3× RTF (медленнее реального времени) | ~0.1–0.3× RTF на RTX 3060+ |
| Silero TTS | ~0.1–0.3× RTF | не нужен |
| VC-инференс (RVC/so-vits) | медленнее реального времени | ~0.1–0.2× RTF |
| VC-обучение (300 эпох, ~10 мин речи) | практически нереально | часы на RTX 3060, меньше на 4090 |

Память: silero-stress ~1 ГБ RAM, Whisper `small` ~1 ГБ, XTTS-v2 ~4 ГБ VRAM
(или ~8 ГБ RAM на CPU). Диск: ~2 ГБ на веса XTTS + ~0.5 ГБ на Whisper.

**Про диалог в реальном времени.** Этот проект — пакетный синтез: он ждёт весь
текст, режет его на чанки и пишет файл. Для живого диалога (речь → ответ →
речь с задержкой до ~1 с) нужны потоковый режим и другое железо:

* GPU уровня RTX 3090/4090 или A10/L4 (24 ГБ) — тогда XTTS даёт RTF ≈ 0.1–0.2
  и первый звук через 200–400 мс при потоковой генерации
  (`Xtts.inference_stream`), плюс параллельно помещаются ASR и LLM;
* RTX 3060/4060 (8–12 ГБ) хватит на связку «Whisper small + XTTS» с задержкой
  порядка 0.7–1.5 с, если LLM внешняя;
* только CPU (8+ ядер): реальное время достижимо с Silero TTS (без
  клонирования, RTF ≈ 0.1–0.3), но не с XTTS;
* к задержке синтеза добавляются ASR (~100–300 мс), LLM (обычно главный вклад)
  и сеть. Ударения силеро на этом фоне почти бесплатны (~90 мс на фразу) и
  кешируются.

Потоковый режим в этом проекте пока не реализован — бэкенд отдаёт готовый
массив сэмплов. Точка расширения для стриминга: `TTSBackend.synthesize`.

## Расширение

**Новый язык** — данными, без правки кода:

```bash
cat > langs.json <<'EOF'
{"languages": [
  {"code": "de", "name": "German", "aliases": ["deu"],
   "whisper_code": "de", "xtts_code": "de", "normalizer": "generic"}
]}
EOF
vctts speak --language-config langs.json -l de -v sample.mp3 -t "Guten Tag!"
```

Или из Python:

```python
from voice_clone_tts.text.languages import LanguageSpec, register_language

register_language(LanguageSpec(
    code="uk", name="Ukrainian", aliases=("ukr",),
    whisper_code="uk", stress_provider="silero", stress_lang="ukr",
))
```

Поля `stress_provider`/`stress_lang` включают акцентор (silero-stress
поставляет `ru`, `ukr`, `bel`), `normalizer` выбирает правила чисел и
сокращений (`ru`, `en`, `generic`), `xtts_code` — код языка для XTTS.

**Новый конвертер голоса** — подкласс `VoiceConverter` с методами `train` и
`convert`, зарегистрированный через `@register_converter`; после этого он
доступен как `--vc <имя>` и в `vctts converters`.

**Новый бэкенд**:

```python
from voice_clone_tts.backends import TTSBackend, register_backend
from voice_clone_tts.text.stress import StressStyle

@register_backend
class MyBackend(TTSBackend):
    name = "my-tts"
    supported_languages = {"ru", "en"}
    clones_voice = True
    native_stress_style = StressStyle.PLUS   # какой вид разметки вам нужен
    sample_rate = 24_000

    def load(self):
        self.model = ...            # тяжёлый импорт только здесь
        super().load()

    def synthesize(self, request):  # -> np.ndarray float32, моно
        return self.model(request.text, request.profile.reference_paths())
```

`vctts speak -b my-tts …` подхватит его сразу, как и `--backend-option k=v`.

## Python API

```python
from voice_clone_tts import PipelineConfig, build_profile, synthesize

config = PipelineConfig()
config.synthesis.backend = "xtts"
config.asr.model = "medium"

profile = build_profile("sample.mp3", out_dir="profiles/anna", config=config)
print(profile.describe())

result = synthesize(profile=profile, text="Привет!", out_path="out.wav", config=config)
print(result.describe(), result.prepared_text, sep="\n")
```

## Качество: что реально влияет

* 30–60 секунд чистой речи одного человека дают заметно лучший результат, чем
  5 секунд; больше 2–3 минут почти ничего не добавляют;
* музыка, реверберация и шум клонируются вместе с голосом — их лучше убрать
  до подачи на вход;
* клиппинг (перегруз) портит тембр сильнее, чем тихая запись: предупреждения
  из отчёта о качестве стоит читать;
* для длинных текстов уменьшайте `--max-chars`, если слышите «зацикливание»
  в конце фраз (типичная болезнь авторегрессионных TTS).

## Этика и право

Клонирование голоса требует согласия человека, чей голос клонируется. Во
многих юрисдикциях голос — персональные данные и объект смежных прав, а выдача
синтезированной речи за настоящую может быть противоправной. Веса XTTS-v2
разрешены только для некоммерческого использования (CPML). Проверяйте, что у
вас есть право на исходную запись.
